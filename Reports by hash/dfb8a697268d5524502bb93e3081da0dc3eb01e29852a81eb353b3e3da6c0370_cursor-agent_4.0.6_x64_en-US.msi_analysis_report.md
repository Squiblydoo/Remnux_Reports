## 2. Classification

**PUA / Riskware — "Cursor Pool" (车队) AI-subscription account-sharing client with local TLS-MITM capability.**
Confidence: **High** (based on direct string/config evidence and decompiled root-CA-generation code, not signature/YARA guesswork).

This is **not** the genuine Anysphere `cursor-agent` CLI. It is a third-party Rust/Tauri desktop application that impersonates it (same product name, icon, and file description) while actually implementing an account-pool/reseller client for Cursor, Claude Code, and AWS Kiro/CodeWhisperer subscriptions. Evidence:

- Embeds config schema and generator code for a self-signed certificate literally named **"Cursor Hook Root CA"** (`sub_14065d580` builds an X.509 cert with commonName `"Cursor Hook Root CA"` and writes `root.crt` to disk — confirmed via decompilation).
- Ships a `proxy_ca` module (`src\proxy_ca\handlers\run_sse.rs`, `proxy_ca_service.rs`, `proxy_ca_config.json`, `proxy_ca_certs`) implementing a local HTTP(S) intercepting proxy with SSE relay support.
- References the real installed Cursor IDE directly: `%LOCALAPPDATA%\Programs\cursor\Cursor.exe`, `...\resources\app\out\main.js`, and a Tauri command `disable_cursor_auto_update_for_injection` — i.e. it patches/hooks the genuine Cursor Electron app and prevents it from auto-updating so the hook keeps working.
- Reads/writes the real Cursor auth state: `cursorAuth/accessToken`, `cursorAuth/cachedEmail`, `WorkosCursorSessionToken=` (Cursor's real session cookie name), and exposes a `switchCursorAccount` API — i.e. it swaps in pooled/shared premium account sessions.
- Contains a hardcoded-looking live-format session credential string: `WorkosCursorSessionToken=user_01K79BM7BMRFSBJSRQ6DRXT471::` (may be a stale/sanitized sample value, but is in the exact production token format).
- Talks to a Chinese backend admin panel `admin.92xx.vip` running the BladeX Java admin framework (`/api/blade-system/...`, `/api/blade-auth/...`) for: guest/user registration, WeChat QR-code login, card-key (卡密) activation and balance conversion (`cardKey/useNew`, `cardKey/balanceToCardKey`), quota (`user/getAmount`), announcements, and self-update version checks (`cursorversioninfo/getVersionInfo`, minisign-signed).
- Pulls remote config from an Alibaba Cloud OSS bucket literally named **`cursorpool`**: `https://cursorpool.oss-cn-guangzhou.aliyuncs.com/config.json`.
- Contains hardcoded backend relay endpoints exposing an OpenAI-style chat API, used to proxy AI chat-completion requests through the pooled/shared accounts: `http://{43.242.200.6,8,48,55,119 | 149.88.92.191,227}:3001/v1/chat/completions`.
- Also manages AWS Kiro accounts (`write_kiro_account`, `get_kiro_history_accounts`, `update_kiro_account_usage`) and references `codewhisperer.us-east-1.amazonaws.com` / `prod.us-east-1.auth.desktop.kiro.dev` — the pool covers multiple AI-IDE subscriptions, not just Cursor.
- Bundles the actual ripped Cursor product web UI (Tauri frontend assets: `ClaudeView`, `BillingView`, `KiroHistoryView`, `CursorProView`, `CursorDashboardView`, `CursorAccountView`, `CursorSettingsView`, `CursorHistoryView`) — the app presents itself with Cursor's own look-and-feel to appear legitimate.

**KesaKode**: Online lookup score maxed at 1.09% ("Splinter") — below the 20% noise threshold, **discarded**, no family attribution from KesaKode. Offline verdicts (Splinter/Funksec/CowardlyDog/Venon, all <2%) are likewise noise.

**YARA (malcat)**: `KeyloggerApi`, `PostHttpForm`, `FingerprintEnvironment`, `RunShell`, `Powershell`, `ValuableFileExtensions` all fired, but all are low/medium-reliability generic API-pattern rules. Given the confirmed Tauri/GUI context (global-shortcut hooking, HTTP client, `GetComputerNameEx` fingerprinting for device-binding, PowerShell used only for the legitimate WebView2 bootstrap — see Attack Chain), none of these indicate classic keylogging/destructive capability; they are explained by ordinary desktop-app functionality. `ValuableFileExtensions` (reliability 20) is very likely a coincidental string-list match and is **not** evidence of ransomware behavior.

## 3. Capabilities

- Installs a self-signed root CA ("Cursor Hook Root CA") into the local trust store to perform TLS interception of the genuine Cursor/Kiro/Claude Code desktop clients' HTTPS traffic.
- Runs a local intercepting proxy (SSE-capable) that rewrites/redirects authenticated API traffic between the real IDE client and cursor.com / AWS / Anthropic-style endpoints.
- Reads and overwrites the real Cursor IDE's local auth storage (access token, cached email, `WorkosCursorSessionToken`) to swap in a different (pooled/shared) premium account.
- Disables Cursor's built-in auto-update to keep its hook compatible.
- Communicates with a Chinese reseller/admin backend for account registration, WeChat OAuth login, card-key (卡密) activation/balance management, and quota enforcement — i.e. monetizes shared AI-subscription access.
- Relays AI chat-completion requests through a fixed set of hardcoded backend IPs, presenting an OpenAI-compatible API.
- Manages a local SQLite database (`cursor_agent.db`) of pooled Cursor/Kiro account records, usage, and billing history.
- Fetches remote operational config from a public Alibaba Cloud OSS bucket and verifies update authenticity via an embedded minisign public key.
- Ships a full Tauri/WebView2 GUI cloned to visually resemble Cursor's own dashboard (billing, history, account, settings views).

## 4. Attack Chain

1. **Delivery**: MSI installer masquerading as the official `cursor-agent` CLI, signed with a legitimate but unrelated Chinese EV certificate.
2. **Install**: WiX-driven MSI extracts `cursor-agent.exe` + icon assets from `app.cab`; a `DownloadAndInvokeBootstrapper` CustomAction runs hidden PowerShell to silently download and install Microsoft Edge WebView2 Runtime (standard Tauri dependency bootstrap — benign in isolation, but note it is a "download-and-execute-arbitrary-URL-content" PowerShell primitive baked into the installer). `LaunchApplication` CustomAction then auto-launches the app post-install.
3. **First run**: the Tauri app installs the "Cursor Hook Root CA" into the Windows trust store and stands up a local intercepting proxy in front of the genuine, separately-installed Cursor IDE.
4. **Account provisioning**: user logs in via WeChat QR or registers a guest account against `admin.92xx.vip`; redeems a card-key to draw from the shared account pool.
5. **Operation**: the tool swaps the real Cursor client's session token for a pooled account's token (`switchCursorAccount`) and/or proxies AI requests through the hardcoded `*.3001/v1/chat/completions` relay nodes, deducting usage against the user's card-key balance.

## 6. Emulation Results

Not performed. The payload is a 34MB Rust/Tauri GUI application with heavy static linking (sqlite, aws-lc/rustls, tokio, hyper) and no isolable "decrypt" primitive suited to speakeasy/angr concrete emulation — its interesting behavior (root-CA install, account-pool network calls) requires a live WebView2 runtime and user interaction (login/card-key redemption) to trigger, which static emulation cannot reach. capa timed out twice (300s) against the 22MB `.text` section and was not pursued further given the classification was already well-supported by string/decompilation evidence.

## 8. Analyst Notes

- This tool sits in a gray zone between PUA and active security risk: installing a locally-trusted MITM root CA and handling/redistributing another service's session tokens are both **security-relevant regardless of intent**. Any host running this software has a "Cursor Hook Root CA" trusted for TLS interception, which materially weakens that host's TLS trust model beyond just Cursor traffic.
- The valid, currently-active EV code-signing certificate (杭州思维宇宙科技有限公司 / Certum, serial `04ff695828a8ed5c859714dc9f20d6d3`) should be considered for revocation reporting, as it is being used to sign a tool that redistributes/pools third-party paid-service credentials.
- The embedded `admin.92xx.vip` / `cursorpool` OSS bucket / `claudecode.top` infrastructure is consistent with the "AI IDE 车队" (account-pooling) genre well known in Chinese developer communities, monetized via card-key (卡密) resale — this is a ToS-violation/piracy tool for Cursor, Claude Code, and AWS Kiro subscriptions rather than a conventional stealer/RAT/ransomware.
- Residual gap: could not confirm at runtime whether the tool *uploads the installing user's own* real Cursor session token to `admin.92xx.vip` (i.e., whether "contributing" a seat to the pool is opt-in or automatic) — this would elevate the classification from "piracy tool" to "credential exfiltration." Recommended follow-up: interactive dynamic analysis (manual GUI walkthrough with a decoy Cursor Pro account) to observe whether `cursorAuth/accessToken`/`WorkosCursorSessionToken` values are read from the local Cursor install and POSTed to `admin.92xx.vip` before or independent of any card-key redemption action.
- No evidence of destructive, ransomware, or classic backdoor/RAT capability was found; `ValuableFileExtensions` and `KeyloggerApi` YARA hits are assessed as false positives from generic desktop-app API usage.
