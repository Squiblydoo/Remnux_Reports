## 2. Classification

- **KesaKode (offline):** SparkRAT 27% — hypothesis only, per policy.
- **KesaKode (online, authoritative):** SparkRAT 16.2%, Glupteba 4.9%, all others <1%. All scores fall **below the 20% threshold** → discarded as noise per report policy. No family attribution.

This looks like a custom-built pivot/tunnel implant rather than a repackaged known tool.

## 3. Capabilities

Reverse-engineered from decompiled `linkclient`/`linkcommon` code and corroborated by capa:

- **Network tunneling / reverse proxy ("jump-client")**: `linkclient.client.core.(*LinkClient)` establishes an outbound TCP connection (`net.Dialer.DialContext`, `tcp4`) to an operator-controlled host, performs a binary handshake (writes a 2-byte magic + 13/17-byte metadata frame), then enters a heartbeat loop (read-deadline'd reads, logged as `"hear"` / `"connect heart error"`).
- **Command channel → SOCKS5-style connect-back**: on receiving a frame, `(*LinkClient).handle` parses a SOCKS5-style address-type byte (`0x01`=IPv4, `0x03`=domain, `0x04`=IPv6) plus target address/port, then spawns a new goroutine (`handle.func3`) that opens a fresh connection to that target and relays traffic — i.e. this component turns the host into a network pivot/backconnect proxy for the operator.
- **Custom encrypted control-channel:** `linkclient.auto.encrypt.(*AesEncrypt).Encrypt/Decrypt` implement AES-CBC via Go's `crypto/aes` + `crypto/cipher`. A **hardcoded AES-128 key/IV pair** was recovered as standalone strings feeding directly into the encryptor object construction in `main.Start`:
  - Key: `dkeilescfal12dfe`
  - IV: `kdleiclzlekdlfld`
- **Externally-supplied C2 configuration**: the DLL's `Start(a, b, c, d)` export takes the C2 address list (comma-split via `strings.genSplit`) and an internal "mask" secret (`dsafasdfelakfdsjlfk`, gates verbose/`debug` vs `disable` logging and writes to `./vauto.log`) as **caller-supplied parameters** — this component ships with **no hardcoded C2 domain**; the operator/loader that invokes `Start()` supplies it at runtime. This is why sandboxing the DLL standalone produces no network activity (see §7).
- **SOCKS5 proxy client library** (`golang.org/x/net/proxy`: `DialWithConn`, `Authenticate`, `socksUsernamePassword`) is linked, including generic `.onion` address-type handling (flagged by malcat's `TorUsage` YARA rule) — this is a capability of the linked SOCKS5 client, not confirmed evidence of an active Tor circuit in this sample.
- **HTTP client with form-POST support** (`application/x-www-form-urlencoded`, malcat `PostHttpForm`) — full Go `net/http`+`crypto/tls` stack is linked (TLS 1.2/1.3, X.509 validation, HTTP/2), likely as a fallback/alternate transport to the raw TCP tunnel.
- **Process enumeration**: imports `CreateToolhelp32Snapshot`/`Process32NextW` (malcat `EnumerateProcesses`) — common for environment/security-product fingerprinting or target-process discovery.
- **Rate limiting** on tunneled traffic via `github.com/juju/ratelimit` (token-bucket, configurable via `Start()` parameters).
- **DNS/config setter methods** on the client object: `SetDns`, `SetNum` (connection-count control).
- capa additionally flags a broad Go-stdlib crypto/hash surface (RC4, ChaCha20/Salsa20, SHA-1/224/256, HMAC, CRC32, MurmurHash/FNV, Base64, QuickLZ decompression) and anti-analysis traits (software-breakpoint detection, stack-string obfuscation) — largely a byproduct of the full Go crypto/TLS standard library being statically linked, not necessarily all actively exercised. capa's "process inject" (RWX memory alloc) and "credit card parsing" flags are typical false positives for Go binaries (Go runtime/GC RWX pages; Luhn-style checksum code coincidentally matching card-number heuristics) — not corroborated by any decompiled credential/injection logic and should not be treated as confirmed capabilities.

## 4. Attack Chain

Only this component's role is directly observable; the loader/dropper that supplies its C2 parameters was not available for analysis.

1. **Delivery/staging** (unknown — outside this sample): `DecManSrv.dll` is dropped under a name suggesting disguise as a legitimate Windows "service" DLL.
2. **Side-load/hosting**: some external process or Windows service calls the exported `Start(domains, mask, ...)`, supplying the operator's C2 address list and the debug-mode secret.
3. **Beacon**: the DLL dials out over raw TCP (`tcp4`) to the supplied address, completes a proprietary AES-encrypted handshake, and begins heartbeating.
4. **Pivot/tunnel**: on command, it opens additional outbound connections to operator-specified targets (SOCKS5-style addressing) and relays traffic — functioning as a backconnect proxy/jump box inside the victim network.
5. **Teardown**: `Stop()` export halts the client; `main.Start` self-guards against double-start by calling `Stop()` first if already running.

## 6. Emulation Results

- **Speakeasy (pass 1, generic runner, x86 DLL)**: loaded successfully but produced **zero IOCs**. Expected: Go's runtime initialization (scheduler, GC, TLS setup) is not compatible with speakeasy's minimal Windows API emulation, and the exported `Start()` requires attacker-controlled parameters (C2 domain list, mask secret) that the generic runner does not supply.
- Given that static decompilation of `linkclient`/`linkcommon` already yielded a complete understanding of the wire protocol (handshake, heartbeat, SOCKS5-style command parsing, AES-CBC encryption), further emulation passes (angr concrete-decrypt, custom speakeasy hooks, Qiling) were judged low-ROI and not pursued.
- **Floss**: timed out at 300s without producing output — a known limitation of floss's stack-string deobfuscation against Go binaries (floss itself warned "string deobfuscation may be inaccurate and take a long time" after identifying Go 1.18). Malcat's static string/anomaly analysis (`StackArrayInitialisationX86`: 256 hits, `XorInLoop`: 325 hits) already covered this surface.

## 8. Analyst Notes

- This sample is a **component**, not a complete standalone threat: it has no embedded C2, and its exported `Start()` is clearly designed to be invoked by a separate loader/dropper/service wrapper that supplies the real configuration (C2 domain(s) and a mask secret). That loader was not present in this analysis.
- The internal naming (`linkclient`/`linkcommon`, "jump-client" log prefix) and the SOCKS5-style connect-back command parsing strongly indicate this is a **network pivot / backconnect proxy implant**, conceptually similar in role to tools like Chisel, frp, or Ligolo-ng, but this is a **bespoke, privately-authored Go codebase** (unversioned "devel" modules) rather than a repackaged known open-source tool.
- Recommended follow-up: if a loader/dropper or service binary that calls `DecManSrv.dll!Start` is recovered, prioritize extracting its call-site arguments (the comma-separated C2 domain list and the mask secret) — those will yield the actual network IOC this analysis could not recover. The recovered AES-128 key/IV (`dkeilescfal12dfe` / `kdleiclzlekdlfld`) can be used to decrypt captured heartbeat/tunnel traffic if this protocol is observed on the wire.
- Per the cross-referencing policy, no link is drawn to any previously tracked family/sample in memory: no matching certificate serial, C2/network IOC, config value, build artifact, or payload hash was found against tracked entries.
