## 4. Attack Chain Context

frpc is **inert without a configuration file**. The binary requires a companion `frpc.ini` or `frpc.toml` specifying:
- `server_addr` / `server_port` — the threat actor's frps (server) endpoint
- `auth.token` — shared secret with the server
- Proxy definitions mapping the victim's internal services to the actor's server

No configuration file was found alongside this binary. Without one, frpc attempts to read `./frpc.ini` and exits or waits. This explains the nil emulation results and the ANY.RUN score of 0.

**Typical deployment pattern for this tool:**
1. Threat actor drops both `frpc.exe` and `frpc.ini` to victim host
2. `frpc.ini` configures a reverse tunnel back to actor-controlled `frps` server
3. Actor gains persistent remote access to internal services (RDP, SMB, internal web apps)
4. If TOR is configured, exit node can mask the frps server's real IP

The expired signing cert suggests deployment started before 2026-02-14, with this binary already embedded in the actor's toolkit. The Chinese signing entity (Hunan Jiangwan Technology Co.) warrants investigation as either a fronted shell company or a victim of certificate theft.

## 8. Analyst Notes

### Key Judgments

1. **This is stock frpc v0.65.0**, not a modified or trojanized variant. All strings, the embedded Vue.js admin UI, proxy type names, and behavioral fingerprint match the open-source project exactly. No backdoor was identified beyond the tool's native tunneling capabilities.

2. **The EV signing certificate is the primary threat indicator.** The official frp distribution is unsigned. An EV cert from a Chinese entity (Hunan Jiangwan) was used specifically to make this binary appear trustworthy to EDR products. This is a documented technique: purchasing or stealing EV certs to sign dual-use tools.

3. **CobaltMirage attribution is plausible context but not confirmed.** CobaltMirage (an Iranian APT group documented by MSTIC) has previously signed frpc with EV certificates for their intrusion operations. The KesaKode overlap (38%) is consistent with their frpc usage but does not confirm it — any actor using frpc v0.65.0 would produce similar KesaKode scores.

4. **The missing config file is operationally significant.** This binary was likely staged for delivery to victims alongside a config file. Recovery of the companion `frpc.ini` or `frpc.toml` would reveal the actual C2 server IP/domain and proxy configuration.

### Recommended Follow-Up

- **Hunt for companion files:** Search the originating system/environment for `frpc.ini`, `frpc.toml`, or any `.toml`/`.ini` file dropped alongside this binary
- **Pivot on the cert serial** `2d676645247129b89455a7c2` — search VirusTotal/Censys for other binaries signed with this cert
- **Pivot on cert subject** 湖南江玩科技有限公司 across certificate transparency logs and threat intel platforms
- **Network forensics:** If this was found on a live host, examine network logs for outbound connections to non-standard ports (frpc defaults: 7000/tcp for the server) and any connections that initiated shortly after this binary was dropped
- **Registry forensics:** Check `HKLM\SYSTEM\CurrentControlSet\Services\` for any service created by this binary
