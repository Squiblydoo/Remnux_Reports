## 2. Classification

**Type:** Local Windows credential validation / account-testing utility, disguised as a fake Webroot browser-security extension.

**Confidence: Medium-High** (based on direct decompilation of API call sites and confirmed API resolution via emulation — not on family/YARA attribution).

**KesaKode:**
- Offline: no verdict (`kesakode_verdict: []`)
- Online (authoritative, MALCAT_KEY): no verdict returned — **no family match at any score** → discard for attribution purposes, per threshold policy.
- No YARA family match either (only a generic compiler-pattern hit, `lcclike_uv_01`, INFO level).

This sample is **not attributable to any tracked family** in current signal. Classification below is derived entirely from static/dynamic behavioral analysis of this sample.

**Reasoning:**
The EntryPoint dynamically resolves 5 sensitive Windows APIs via a custom hash-based `GetProcAddress` routine (avoiding static import-table visibility): `LogonUserW`, `NetUserEnum`, `NetWkstaGetInfo`, `GetAdaptersAddresses`, `DialogBoxIndirectParamW`. Decompilation of the call sites shows exact signature matches:

```
(*0x425f54)(0, 0, 2, &iStack_68, 0xffffffff, auStack_78, &uStack_3c, 0)   // NetUserEnum(servername=NULL, level=2, filter, bufptr, prefmaxlen, entriesread, totalentries, resume)
(*0x425f58)(0, 100, &ppcStack_b4)                                         // NetWkstaGetInfo(servername=NULL, level=100, bufptr)
(*0x425f50)(&uStack_474, &uStack_580, &uStack_274, 2, 0, acStack_88)      // LogonUserW(username, domain, password, dwLogonType=LOGON32_LOGON_INTERACTIVE, provider=0, phToken)
(*0x425f4c)(0, 0x80, 0, ppcVar28, auStack_78)                             // GetAdaptersAddresses(family, flags, reserved, pAdapterAddresses, pOutBufLen)
```

A modal dialog (driven by a DialogProc at VA `0x419543`) is populated with a **ListBox** (control ID `0x2c2`, `LB_RESETCONTENT`/`LB_ADDSTRING`/`LB_FINDSTRINGEXACT`), a **ProgressBar** (control ID `0x1ad`), and an **Edit control** (ID `0x354`, max length 127 chars, read via `GetDlgItemTextA` into a buffer immediately before the LogonUserW loop). This matches a UI flow of: enumerate local accounts (NetUserEnum) → populate list → operator enters a candidate password → iterate accounts attempting `LogonUserW` with that password → track progress in the ProgressBar. `NetApiBufferFree` is called for cleanup of the enumeration buffer.

This is consistent with a **local password-validation / account-auditing tool** — used to test whether an operator-supplied (e.g. guessed, leaked, or brute-forced) password is valid against any local Windows account. Such tools are used in post-exploitation/access-broker workflows to confirm a credential works before further lateral movement, or by an attacker with initial local access wanting to identify which accounts share a known password.

**capa's "keylogging via polling" (T1056.001) flag is a false positive.** All 3 static occurrences of `GetAsyncKeyState` are called with a **hardcoded argument of `0`** (not a real virtual-key scan) inside 3 near-identical junk-code blocks of ~30 unrelated Win32/CRT API calls (`GetOEMCP`, `CreatePen`, `ImmGetContext`, `PathFindFileNameA`, etc.), each invoked with null/zero arguments, whose return values are XOR'd together into an unused global (`0x425f44`). This is API-call-flooding obfuscation intended to inflate the import table and confuse capability-detection heuristics (capa, peframe), not genuine keystroke capture.

## 3. Capabilities

- Dynamic/hashed resolution of sensitive APIs to evade static import-table detection (custom multiplicative hash, `× 0x1000097`, walking PE export tables — classic shellcode-style hashing)
- Byte-by-byte arithmetic string deobfuscation (add/subtract constant per byte, decoded at runtime from `.rdata`)
- Enumerates local Windows user accounts (`NetUserEnum`, level 2)
- Retrieves workstation/domain info (`NetWkstaGetInfo`, level 100)
- Attempts interactive logon validation for enumerated accounts against an operator-supplied password (`LogonUserW`, `LOGON32_LOGON_INTERACTIVE`)
- Enumerates network adapters (`GetAdaptersAddresses`)
- Displays a modal dialog (ListBox + ProgressBar + password Edit field) to drive the above workflow interactively
- Displays a decoy `MessageBoxA` with text "The requested resource is in use." (fake error / ERROR_BUSY-style lure text, likely shown as a distraction or fallback)
- Junk-code / API-flooding blocks to pollute static heuristic detection (capa flagged spurious "keylogging" and "get disk information" as a side effect)
- No outbound C2/network exfiltration observed (static or dynamic) — this is a local-only tool

## 4. Attack Chain

1. Execution → dynamic API resolution (hash-based `GetProcAddress` walk) for `LogonUserW`/`NetUserEnum`/`NetWkstaGetInfo`/`GetAdaptersAddresses`/`DialogBoxIndirectParamW`
2. Junk-code blocks execute (anti-heuristic padding), decoy strings decoded
3. `CreateThread` spawns the DialogProc thread (`sub_419543`); a 5-second `SetTimer` callback is also armed
4. Modal dialog shown: enumerates local accounts into a ListBox via `NetUserEnum`
5. Operator (or automated driver) enters a candidate password in the Edit control
6. For each enumerated account, `LogonUserW` is attempted with the supplied password; ProgressBar reflects iteration progress
7. Fallback/decoy: `MessageBoxA` shown with a fake "resource in use" error

No stage of the chain reaches out to network C2 — this is entirely local host activity requiring interactive operator input to be useful (consistent with ANY.RUN showing no automated progression past the initial dialog).

## 6. Emulation Results

Generic speakeasy runner (x86, 120s timeout) successfully resolved and logged 5 hash-based `GetProcAddress` lookups before emulation ended (no further deep trace — DialogBox-driven flow does not proceed without simulated user input):

```
[GetProcAddress] 'DialogBoxIndirectParamW' -> 0xfeee0000
[GetProcAddress] 'LogonUserW'              -> 0xfeee0001
[GetProcAddress] 'NetUserEnum'             -> 0xfeee0002
[GetProcAddress] 'NetWkstaGetInfo'         -> 0xfeee0003
[GetProcAddress] 'GetAdaptersAddresses'    -> 0xfeee0004
```

This is the single most important piece of evidence for classification — it directly resolves what the hash-based import-evasion technique was hiding. No custom hook was required (the generic runner's existing `GetProcAddress` hook handled hash resolution); no updates were made to the shared `hooks.py` library.

## 8. Analyst Notes

- **KesaKode online returned no match** — this sample shares no fingerprint with any family in the KesaKode database. It should not be linked to any tracked campaign or family absent stronger evidence (matching cert serial, C2, config value, PDB path, or payload hash — none of which are present here).
- **capa's keylogging/T1056.001 finding is a false positive** driven by junk-code API-flooding; do not carry this forward as a capability without re-verifying if this sample recurs.
- The carved JPEG (offset 126871, 2546 bytes) and PKCS7 blob (offset 148488, 9754 bytes, in the overlay) were not further inspected — the PKCS7 blob is consistent with the Authenticode signature block; the JPEG is most likely an embedded icon/UI resource and was not prioritized given the confirmed credential-testing capability took analytical priority.
- Two additional heavily-reused helper functions (`sub_401d05` VA 0x401d05, `sub_41b644` VA 0x41b644) were not decompiled — follow-up recommended if this sample or a close variant recurs, to confirm whether any output (validated credentials) is persisted or exfiltrated locally (e.g., written to a file) rather than only displayed in the UI.
- No persistence mechanism (registry Run key, scheduled task, service) was identified in imports, emulation, or sandbox trace — this appears to be a single-run interactive tool rather than a persistent implant.
- Given the fake Webroot/BrowseSecure branding, plausible delivery vector is a trojanized "browser security extension helper" lure to obtain initial execution trust, after which the tool serves as a **post-access credential-validation utility** rather than the initial-access payload itself.
