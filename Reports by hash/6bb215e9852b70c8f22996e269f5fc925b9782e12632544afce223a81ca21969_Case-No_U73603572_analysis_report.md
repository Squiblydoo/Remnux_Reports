## 2. Classification

**Primary Classification:** ScreenConnect Remote Access Abuse — Malicious RMM Deployment  
**Confidence:** High  
**KesaKode Online:** Not applicable (no novel malware code; threat is configuration-based)  
**ANY.RUN:** 100/100 — Malicious activity | Tags: `screenconnect`, `rmm-tool`, `remote`

### Reasoning

This MSI installs a fully legitimate, unmodified ScreenConnect (ConnectWise Control) client (version 25.9.10.9545). The malicious element is entirely in the installer's **configuration**: the MSI `Property` table contains `SERVICE_CLIENT_LAUNCH_PARAMETERS` hard-coding relay host `reley.xevarith.com` — a threat actor-controlled server — rather than a legitimate ConnectWise infrastructure host.

The lure filename `Case-No_U73603572.msi` impersonates a legal case notification to trick victims into running the installer. The code signing certificate (Turkish entity NURHAN KAYIR FIPACK SOLUTIONS) adds superficial legitimacy while being entirely unrelated to ConnectWise/ScreenConnect.

This technique — abusing legitimate remote management tools to establish covert access — is widely used by BEC actors, tech support scammers, and ransomware initial-access brokers. ScreenConnect is a frequent target because it provides full unattended remote control, file transfer, and command execution over TLS on port 443, masquerading as normal HTTPS traffic.

## 3. Capabilities

- **Unattended remote desktop access** (session type `e=Access`, `y=Guest`) — operator can connect at any time without victim interaction
- **File transfer** — `ScreenConnect.WindowsFileManager.exe` provides full bidirectional file manager
- **Remote command execution** — `ScreenConnect.WindowsBackstageShell.exe` provides operator shell access
- **Persistent Windows service** — installs as service `ScreenConnect Client (191310e53e054486)` with `ALLUSER=1` (system-wide) and `REBOOT=ReallySuppress` (silent, no reboot prompt)
- **Windows Credential Provider** — `CREDENTIAL_PROVIDER_CLASS_ID={6FF59A85-BC37-4CD4-1C3F-0B72F46DA9AB}` — hooks the Windows logon screen, allowing credential interception
- **Safe Mode persistence** — registry key `System\CurrentControlSet\Control\SafeBoot\Network\[SERVICE_NAME]` ensures service runs even in Safe Mode with Networking
- **URL protocol handler** — registers `sc-191310e53e054486://` URL scheme, enabling operator to launch sessions via browser/link
- **Privilege escalation capability** — `ScreenConnect.InstallerActions.dll` contains `SeDebugPrivilege`, `AdjustTokenPrivileges`, `CreateToolhelp32Snapshot`, `Process32NextW`, `ShellExecuteW`; uses these to terminate competing processes and adjust service arguments at install time
- **Process enumeration** — enumerates running processes during install to terminate competing ScreenConnect instances

## 8. Analyst Notes

### Key Indicators of Malicious Intent

1. **Typosquatted relay domain** — `reley.xevarith.com` deliberately mimics "relay" to evade casual inspection. `xevarith.com` has no legitimate association with ConnectWise/ScreenConnect.

2. **Foreign code signing certificate** — Legitimate ScreenConnect MSIs are signed by ConnectWise LLC. This MSI is signed by NURHAN KAYIR FIPACK SOLUTIONS (Istanbul, Turkey), a company with no relation to ConnectWise. The SSL.com certificate (issued 2026-05-28) is fresh — likely purchased specifically for this campaign.

3. **Lure filename** — `Case-No_U73603572.msi` impersonates a legal/court case document, a classic BEC/social engineering pattern to induce urgent installation.

4. **Credential Provider installation** — ScreenConnect's legitimate Credential Provider is a documented feature used by MSPs. In this context, it extends the attacker's access to the Windows logon screen, enabling credential harvesting if the victim locks or logs off.

5. **Safe Mode persistence** — Adding the service to `SafeBoot\Network` means the attacker retains access even if the victim attempts to boot into Safe Mode for remediation.

### Gaps and Recommended Follow-up

- **Relay server pivoting:** `46.247.108.73` should be pivoted across passive DNS and certificate databases (Shodan, Censys) to identify additional campaign infrastructure hosted on the same IP or sharing the SSL cert.
- **Instance ID pivoting:** Instance `191310e53e054486` and UpgradeCode `{C1B76AA8-344B-C349-1913-10E53E054486}` can be searched in VirusTotal/Shodan to find related MSI samples from the same campaign.
- **Cert serial pivoting:** SSL.com cert serial `60353ac688fd82a02c36c9043c8ceb09` — check for revocation and pivot for other MSIs signed by the same cert.
- **Campaign context:** The "Case-No" lure is consistent with legal-threat BEC campaigns targeting individuals/businesses. Correlation with email delivery infrastructure is recommended.
- **Remediation:** Uninstall via `msiexec /x {A2B4FB7F-2F7F-77F9-B918-262A25699E39}` or Programs and Features. Remove Credential Provider CLSID `{6FF59A85-BC37-4CD4-1C3F-0B72F46DA9AB}`. Audit `SafeBoot\Network` registry. Rotate credentials if service was active.
