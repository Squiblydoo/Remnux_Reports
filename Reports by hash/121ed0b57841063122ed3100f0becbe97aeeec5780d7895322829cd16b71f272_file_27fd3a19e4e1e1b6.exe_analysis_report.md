## 2. Classification

**Family/type:** "Flotilla" — a Go-based fleet-management installer for a browser-automation botnet, most consistent with a **livestream viewbot / engagement-fraud agent targeting Kick.com**. Confidence: **High** (based on decompiled installer logic, string/config recovery, and confirmed dynamic sandbox behavior — not on family-name attribution, since no KesaKode/YARA family match crossed the confirmation threshold).

**KesaKode:**
- Online lookup: highest hit was `OverlordRAT` at 0.36% — far below the 20% code-overlap threshold. **Discarded as noise; no attribution basis.**
- No offline KesaKode verdict was returned either.

**Malcat YARA:** `Golang` (compiler, informational), `TorUsage` (`.onion` string present — Tor bridge fallback), `DisableAntivirus` (Defender-exclusion PowerShell strings), `EnumerateProcesses` (tasklist-based process polling). All corroborated by decompilation below.

**ANY.RUN verdict:** **100/100 — "Malicious activity"**, tags `auto-reg`, `arch-scr`, `websocket`, `golang`.

This is *not* a generic RAT/stealer/loader — the decompiled `main.main`, `installWindows`, `stopExisting`, `addDefenderExclusion`, and `apiBaseFromBridge` functions (all with original Go symbol names intact) describe a purpose-built **installer for a persistent, remotely-managed browser-automation agent**, and the sandbox run shows it launching a Chromium-based profile that logs into and idles on specific Kick.com livestream channels while soliciting the site's Kasada anti-bot fingerprinting challenge (`kick.com/149e9513.../fp?x-kpsdk-v=...`) — behavior consistent with defeating bot-detection to inflate viewer/chat counts.

## 3. Capabilities

- **Defender evasion (built-in, by design):** requests UAC elevation specifically "for Defender exclusion" (Turkish log strings), then runs a hidden (`-WindowStyle Hidden`) PowerShell one-liner:
  `Add-MpPreference -ExclusionPath '<profile temp dir>'; Add-MpPreference -ExclusionPath '<install root>'; Add-MpPreference -ExclusionProcess 'warden.exe','pilot.exe'`
  — excluding its own two worker binaries by name from AV scanning. Falls back gracefully (continues install) if PowerShell/Defender access fails, logging `EXCLUSION_FAIL`.
- **Self-updating installer framework:** CLI flags `-manifest`, `-root`, `-bridge`, `-secondary`, `-pubkey`, `-runtime-cmd`, `-machine-id`, `-tags`, `-browser`. Fetches a JSON release manifest, downloads a `.tar.gz` bundle, verifies against a baked-in Ed25519-style update public key (`main.bakedPubkey`), extracts to a versioned directory, and atomically switches a `current` symlink (`Layout.SwitchTo`).
- **Old-instance cleanup:** `taskkill /F /T /IM warden.exe` and `.../pilot.exe`, then polls `tasklist /FI "IMAGENAME eq warden.exe"` every 700ms (up to 12 tries) until confirmed dead before reinstalling.
- **Persistence:** writes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Flotilla` pointing at the installed `warden.exe` (unless `-no-autostart`); also removes a legacy `FlotillaKeeper --keeper` Run entry from prior versions.
- **Machine enrollment / fleet management:** builds an agent config with `FLOTILLA_MACHINE_ID`, `FLOTILLA_TAGS` ("policy tags"), `FLOTILLA_BRIDGE` (primary C2), `FLOTILLA_SECONDARY_URL` (fallback C2), `FLOTILLA_MANIFEST_URL`, `FLOTILLA_REPORT_URL` (`<bridge>/agent/report`), writes it via `Layout.WriteAgentConf`, and registers the machine via `/api/machines`.
- **Tor bridge fallback:** YARA `TorUsage` + literal `.onion` string; `-bridge`/`FLOTILLA_BRIDGE` flag documented as the "primary bridge WS address," implying an onion fallback path for censorship/blocklist resistance.
- **Covert C2 channel:** default C2 is `flotilla.45-94-31-71.sslip.io` — a raw IP (45.94.31.71) wrapped in the free wildcard-DNS service sslip.io. This lets the operator obtain a real, browser-trusted TLS certificate for what is functionally a bare IP address, evading domain-reputation and typosquat-based blocklists. Confirmed live in ANY.RUN traffic.
- **Browser automation payload:** two deployment modes selected by `-browser`:
  - `cdp` — drives the **system's real Chrome/Edge** via Chrome DevTools Protocol (`FLOTILLA_BROWSER=cdp`), using per-target profile directories under `<root>/profiles` (`FLOTILLA_BROWSER_DIR`, on-disk as `flotilla-profiles`).
  - default — launches a bundled Electron runtime (`<root>/current/runtime/electron/electron.exe`).
  Confirmed in ANY.RUN: separate Chromium profile directories named `kick.com-seroxxoffical` and `kick.com-poast` under `C:\Users\admin\AppData\Local\Flotilla\profiles\`, each independently loading `https://kick.com/<channel>` with full ad-tech/analytics/CDN traffic (i.e., a real, fingerprint-passing browser session per target channel).
- **Watchdog/worker split:** installs and autostarts `warden.exe` (supervisor, logs to `warden.log`), which in turn launches `pilot.exe` (the automation worker) — both explicitly Defender-excluded by name.
- **NetUserEnum / GetComputerNameEx / registry APIs** imported — consistent with local machine fingerprinting for the `FLOTILLA_MACHINE_ID`.

## 4. Attack Chain

1. `setup.exe` (this sample) runs, requests elevation, and (unless suppressed) silently adds Windows Defender path/process exclusions for its own components via hidden PowerShell.
2. Fetches the release manifest from `https://flotilla.45-94-31-71.sslip.io/agent/manifest`.
3. Kills any pre-existing `warden.exe`/`pilot.exe`, waits for confirmed termination.
4. Downloads and extracts the versioned bundle (`.tar.gz`) to `%LOCALAPPDATA%\Flotilla\`, switches the `current` version symlink.
5. Writes an agent config (`FLOTILLA_*` env vars) wiring the install to its C2, machine ID, tags, and either a CDP browser-automation target or a bundled Electron runtime.
6. Installs `HKCU...\Run\Flotilla` persistence pointing at `warden.exe`.
7. Launches `warden.exe --root <install dir>` as a detached background process; `warden.exe` opens a persistent WebSocket connection to the C2 (`wss://flotilla.45-94-31-71.sslip.io/agent`) and spawns `pilot.exe`.
8. `pilot.exe`/the browser-automation component opens one Chromium profile per assigned target and navigates to specific Kick.com livestream channels (observed: `kick.com/seroxxoffical`, `kick.com/poast`), joins the site's WebSocket chat/viewer channel (`websockets.kick.com/viewer/v1/token`), and idles — generating fraudulent viewer/engagement activity while presenting as a real, fingerprint-passing browser session.

## 6. Emulation Results

- **Speakeasy (pass 1, generic runner, amd64, 90s timeout):** stalled immediately after resolving `bcryptprimitives.dll` via `LoadLibraryExW` — no further API activity captured. This is expected: Go's runtime scheduler/threading model and its own syscall stubs are not compatible with speakeasy's Windows API emulation, so execution effectively halts during Go runtime init before reaching `main.main`. **Emulation was not pursued further** (passes 2–4) — static decompilation of Go-symbol-intact functions plus confirmed dynamic sandbox execution already provided complete behavioral coverage, making further emulation low-value for this binary.
- **capa:** did not complete within the available time budget (repeated timeouts at 180s/250s) against this 7.4 MB Go binary — the executable's size and code volume made rule matching too slow to finish in-session. Not included.
- **floss (`--only decoded`):** did not converge within the available time budget; Go static-string deobfuscation is known to be slow/inaccurate per floss's own warning banner. Not included. Static strings + `strings`-based stringsifter ranking (below) provided equivalent coverage since this binary is largely unobfuscated Go with symbol names intact.
- **stringsifter** (ranked static strings, top results): confirmed all Turkish-language operator strings (Defender-exclusion prompts/failures, "old processes being stopped", "Flotilla agent config" header), the SSL.com cert chain URLs, and the Go/Homebrew build path `/opt/homebrew/Cellar/go/1.26.5/...` (built on macOS with a very recent Go toolchain).
- **peframe:** confirms mutex/registry/network(tcp/udp/dns)/win-token/AES/base64 feature flags consistent with the above; no additional findings beyond malcat/capa-equivalent signals.

## 8. Analyst Notes

- **What this is, and isn't:** this is not a credential stealer, ransomware, or classic backdoor RAT — it is an installer for a commercial-grade browser-automation "fleet" agent. The specific evidence (per-channel Chromium profiles, Kasada fingerprint-challenge traffic, viewer/chat WebSocket joins on named Kick.com streamer channels) points strongly at **livestream viewbot / engagement-fraud-as-a-service**, likely sold or rented to streamers/operators wanting to inflate Kick.com viewer counts or chat activity. This framing is inference from behavior, not a named-family confirmation — no vendor/YARA/KesaKode signal names this tooling, so treat "Flotilla viewbot" as a working hypothesis, not a confirmed brand.
- **Turkish-speaking operator:** all embedded operator-facing log strings (`Yonetici izni isteniyor...`, `Defender muafiyeti eklenemedi...`, `Eski surecler durduruluyor...`) are Turkish, consistent with a Turkish-speaking developer/operator base — plausible given Kick.com's large following among Turkish streamers/audiences.
- **Fresh signing cert as a standing detection opportunity:** the SSL.com cert (serial `2cab81c2bf9f63865b3079321aa137b3`, subject "SERHAT DOGAN") was issued the same day as this sample — worth flagging to signing-cert-reputation feeds; likely to be reused across a short-lived batch of builds before rotation.
- **Residual gaps:** `pilot.exe` and the downloaded `.tar.gz` bundle content were not recovered/analyzed in this pass (network egress from this host to fetch the actual manifest/bundle was not attempted — see [[reference_remnux_network_pivot_options]] for known connectivity limits from this REMnux host). The ANY.RUN run captured genuine bundle execution dynamically, which substitutes for static bundle analysis here. capa/floss did not complete for this binary; if deeper capability-rule coverage is needed later, consider running capa with `--restrict-to-functions` scoped to the ~15 `main.*`/`github.com/flotilla.*` functions identified here rather than the whole 7.4MB image.
- **Recommended follow-up:** pivot on the C2 IP `45.94.31.71` and the sslip.io wildcard pattern (`flotilla.<any-ip>.sslip.io`) for related samples/infrastructure; consider submitting the cert serial to reputation tracking given its same-day issuance.
