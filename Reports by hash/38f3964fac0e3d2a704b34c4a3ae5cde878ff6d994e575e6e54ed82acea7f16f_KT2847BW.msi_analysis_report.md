## 2. Classification

**Trojanized/repackaged legitimate-software installer wrapper — confidence: medium-high.**

This is not a modified malware sample in the traditional sense (no injected code was found in any executed binary). It is a genuine, unmodified **Open Salamander 4.1** (a Czech open-source dual-pane file manager, formerly "Altap Salamander") installer, rebuilt into a new Advanced Installer MSI package and re-signed with a Microsoft Trusted Signing certificate issued to an unrelated shell/burner business identity ("Alsace Music ApS"). Embedded inside the package, tied to the legitimate `automation.spl` plugin component, is a single anomalous 105 MiB file of near-maximum-entropy (7.9999 bits/byte) random data with a randomized 6-character filename (`RwQnH`) and no visible reference anywhere in the shipped code.

No PE/ELF/Mach-O malware payload was identified for KesaKode fingerprinting — the only anomalous artifact (`RwQnH`) is not a valid executable, archive, or otherwise-structured file, so online KesaKode lookup does not apply to it. All extracted PE binaries (`salamand.exe`, `salmon.exe`, `salextx64.dll`, `salextx86.dll`, plugin `.spl` modules, `aicustact.dll`, and Advanced Installer/WinUI3 runtime DLLs) are unmodified components of Open Salamander or Advanced Installer/Windows App SDK redistributables.

**Key evidence:**
1. `salamand.exe` retains its original valid Authenticode signature (Fine spol. s r.o., 2019) with matching digest — proves the actual application was not tampered with.
2. `AI_APP_FILE` property = `[#ThunderbirdPortable.exe]` — a **leftover reference to an unrelated portable application** (Mozilla Thunderbird Portable) that does not exist in this package's File table. This is strong evidence the installer was built from a reused generic Advanced Installer template/builder (consistent with a bundler-for-hire or PPI-style packaging pipeline that wraps arbitrary third-party software), rather than an installer authored by the actual Salamander developers.
3. `RwQnH` is registered in the MSI `File` table (`Component_=automation.spl`, `FileSize=110100480`, `Sequence=643` — appended after all legitimate rows) — it will be **silently written to disk** at `%LocalAppData%\Altap Salamand\plugins\automation\RwQnH` (or equivalent APPDIR path) during a completely normal-looking install, with no separate Feature/Component of its own and no CustomAction referencing it.
4. `RwQnH` entropy = 7.9999 bits/byte (indistinguishable from CSPRNG output); size is **exactly 105 × 1024² bytes**, a deliberately round, page-aligned figure rather than an organically-sized real payload.
5. No string `"RwQnH"` and no loader/decryption logic referencing this filename was found in any shipped binary — the blob is inert with respect to the code in this package.

## 3. Capabilities

As shipped, this package's *executed* code is simply the legitimate Open Salamander file manager installer/application — dual-pane file management, archive plugins (7-Zip, tar, checksum, ftp, etc.), shell integration (`salextx64.dll`/`salextx86.dll` shell extensions), and standard Advanced Installer/WinUI3 bootstrapper UI (WebView2, Microsoft.UI.Xaml). None of this is malicious.

The anomalous behavior is limited to:
- Silently dropping a 105 MiB high-entropy blob to disk under the Salamander plugin directory during install, with no code path in this package that reads, decrypts, or executes it.

## 4. Attack Chain

Only a partial chain can be established from static evidence alone:

1. **Distribution** — MSI presented as an Open Salamander file-manager installer (likely via SEO poisoning, malvertising, or a fake download site — not observable from this artifact alone).
2. **Trust lending** — Package signed with a Microsoft Trusted Signing certificate obtained under the shell identity "Alsace Music ApS", giving the installer a "Verified publisher" prompt in Windows SmartScreen/UAC despite having no relation to the actual software.
3. **Install** — Genuine, functional Open Salamander 4.1 is installed normally (this is likely intentional: a working legitimate app reduces user suspicion).
4. **Silent drop** — `RwQnH` (105 MiB random blob) is written to the plugins\automation directory as a side effect of the MSI's File table, with no built-in trigger to execute or use it.
5. **Unknown/unresolved stage** — No mechanism in this package activates `RwQnH`. Either (a) it is purely an anti-analysis/anti-sandbox size-inflation artifact intended to push the installer past automated sandbox/AV upload size limits (a technique previously observed in this workspace on unrelated large "padded" samples), or (b) it is a placeholder for a payload that a separate, not-included component (a follow-on downloaded script, scheduled task, or manual operator action) is meant to decrypt/rename/execute later. Static analysis cannot distinguish between these with certainty.

## 6. Emulation Results

Not performed. There is no identified malicious entry point or decrypt routine to emulate — `RwQnH` is not a PE/script and no code in the package references it, so speakeasy/angr emulation would have no target. capa/floss analysis of `salamand.exe` was attempted but not completed (tooling timeout on the 3 MB legitimate binary); given the binary's Authenticode digest independently verifies as the genuine, unmodified publisher release, further static capability scanning was deprioritized.

## 8. Analyst Notes

- **Primary residual gap:** the purpose of `RwQnH` could not be conclusively determined from static analysis alone. Its precise 105 MiB (105 × 1024²) size, maximal entropy, and complete lack of any referencing code favor an **anti-sandbox / anti-AV size-inflation padding** hypothesis over a "hidden encrypted second-stage payload" hypothesis — but the latter cannot be ruled out, since the blob is placed as a real installed file (not a harmless post-EOF overlay), which would be an unusual amount of effort to spend purely on padding.
- **Reused-builder artifact:** the dangling `AI_APP_FILE=[#ThunderbirdPortable.exe]` property is a strong signal that the actor's packaging pipeline is a generic/templated Advanced Installer builder capable of wrapping arbitrary third-party software (Open Salamander here; potentially unrelated software in other builds from the same pipeline). This is a distribution-tooling fingerprint, not a code-level IOC, and per this workspace's cross-reference policy does not meet the bar (no matching cert serial, C2, config value, build path, or payload hash) to be linked to any previously analyzed sample.
- **Certificate abuse pattern:** the 3-day "Microsoft ID Verified CS AOC CA 04" certificate under a business name with no connection to the software being signed matches a broader, well-known abuse pattern of Microsoft's Trusted Signing service (low-friction identity vetting enabling quick disposable EV-equivalent certificates) — this is a systemic technique, not a unique attribution marker.
- **Recommended follow-up:** if a live distribution URL or a "clean" reference build of this exact MSI package (without RwQnH) becomes available, diffing the File tables would confirm whether RwQnH is unique to this drop or a running campaign constant. Sandbox detonation (with a size-limit-tolerant sandbox, or after manually stripping RwQnH from a copy to fit upload limits) would help determine whether any other component of the Windows environment (e.g., Windows Search indexing, AV engines scanning plugins\automation) is expected to interact with this file, and whether the genuine `salamand.exe` process ever attempts to read it at runtime despite the absence of a static string reference (e.g., via a computed/obfuscated path).
