## 2. Classification

**Verdict: Genuine Microsoft-signed executable — not malware.** This is a **Product Specific Installer (PSI)** stub, the binary produced by Microsoft's own "Get it from the Microsoft Store" badge/link generator (used by third-party web pages to launch a direct install of a specific Store app). Confirmed via full decompilation (`ilspycmd`) of the `Launcher`/`TagExtractor`/`PayloadV1` classes:

- The binary carries a signed, tamper-evident metadata payload embedded as a custom X.509 extension (OID `1.3.6.1.4.1.11129.2.1.9999`) inside a secondary `CN=Dummy certificate` / `Issuer=CN=Unknown issuer` cert stapled into the PKCS7 signature blob (alongside the real Microsoft signing chain — this dual-certificate structure is intentional and matches Microsoft's own PSI generator design).
- The payload is RSA-SHA256-signed against an embedded public key (`StoreInstallerPublicKey.bin` resource) and was cryptographically verified successfully during this analysis.
- Decoded payload identifies the target Microsoft Store listing:
  - **productId**: `XPFFGCPBQ8TDT4`
  - **title**: "T2Auth Bastion"
  - **publisher**: "Yanasofts"
  - `installerType: WPM`, rated "Everyone" (ESRB/PEGI/etc.), 200+ markets, `referrer: storeforweb`
- At runtime the binary simply invokes `Process.Start("ms-windows-store://pdp?productid=XPFFGCPBQ8TDT4&ocid=webpdpshare&referrer=psi")`, handing off to the real Windows Store client / `apps.microsoft.com` web flow to resolve and install the target package. All hardcoded endpoints (`sfdataservice.microsoft.com`, `storesdk.dsx.mp.microsoft.com`, `displaycatalog.mp.microsoft.com`, `storeedge.microsoft.com`, `apps.microsoft.com`, `bat.bing.com` for conversion telemetry) are legitimate first-party Microsoft Store infrastructure.
- No packer, no obfuscation, no hidden/embedded payload beyond standard WPF UI resources (icons, PNGs, BAML XAML) and the PKCS7 signature block (confirmed via `file_list_virtual_files`/`file_list_carved` — nothing anomalous).

**Cross-reference — matches an existing tracked entry**: The embedded, cryptographically-verified payload's `title` field ("T2Auth Bastion") is an **extracted config value that matches** the `VersionInfo::ProductName` ("T2Auth Bastion" v12.2.5) recovered from `T2Auth_Bastion.exe` (SHA256 `9f6314a4cdb784ce153e1bddc8488d4d20f59b7ec4c6cfc189a4bbb403d9cc61`), analyzed earlier today and recorded as suspicious-but-unconfirmed (ANY.RUN 100/Malicious, Advanced Installer bootstrapper signed by a near-dormant Norwegian shell entity "PROGRAMVARE PARTNER ANS" for publisher "Mykhacode", zero independent web presence — see `project_t2auth_bastion_advinstaller_ambiguous.md`). Notably, the Microsoft Store listing shows publisher **"Yanasofts"**, while the binary's own signed metadata claims publisher **"Mykhacode"** — a discrepancy worth flagging to Microsoft Store integrity/trust teams, since it suggests the Store-listing publisher identity and the installer's internal signer identity don't agree.

**This file itself is not malicious code.** It is Microsoft's own legitimate distribution mechanism, being used (whether by the "T2Auth Bastion" publisher's marketing/website or by a third party) to drive installs of an app whose own behavior remains unresolved from prior analysis.

## 3. Capabilities

- Reads a signed metadata "tag" embedded in its own Authenticode certificate table to determine which Microsoft Store product to install (productId, title, publisher, markets, age ratings, min-OS requirements).
- Single-instance enforcement via named mutex `Global\{f6bec8ba-58ff-4dfc-9981-2ec5ebd23734}-<PRODUCTID>`.
- Supports `--silent`, `--allusers`, `--uninstall` command-line switches for unattended install flows.
- If not silent: launches `ms-windows-store://pdp?productid=...` to hand off to the real Store client/web UI.
- If silent/all-users: drives the install itself via `PackageManagerDeployer` / `WuInstaller` / `WpmInstaller`, resolving the package through Microsoft's Package Retrieval Service (PRS) at `sfdataservice.microsoft.com`, staging to a secure reparse-point-protected directory (explicit anti-symlink-attack checks present in code — `SecureStagingDirectory`), writing result/inventory keys under `HKLM\SOFTWARE\...\Installer\Inventory\`, and emitting first-party Microsoft telemetry (Asimov/UET) throughout.
- Checks Windows Update policy state (`wuauserv` service status, `SOFTWARE\Policies\...\WindowsUpdate`) to decide install pathway.
- Reads DWM/theme registry values purely for UI theming (dark/light icon selection).

## 4. Attack Chain (as a distribution vector, not as malicious code)

1. User obtains `StoreInstaller.exe` (e.g., from a "T2Auth Bastion" marketing page using Microsoft's official PSI badge).
2. Execution → tag extraction confirms embedded, Microsoft-signed target: productId `XPFFGCPBQ8TDT4` ("T2Auth Bastion").
3. `ms-windows-store://pdp` handoff opens the real Microsoft Store listing (or resolves/installs directly in silent/all-users mode).
4. The Microsoft Store install flow downloads and installs the actual "T2Auth Bastion" package — this is where any actual malicious payload, if present, would execute, and is outside this binary's own code (see `T2Auth_Bastion.exe` prior analysis for the closest available window into that product, itself unresolved).

## 8. Analyst Notes

- The file itself is legitimate, Microsoft-signed code performing exactly its documented function (a Store product badge/installer stub). No malicious code, obfuscation, C2, or hidden payload was found anywhere in the binary.
- The interesting/actionable finding is entirely in the **target it points to**: Microsoft Store productId `XPFFGCPBQ8TDT4` ("T2Auth Bastion", publisher "Yanasofts" per the Store listing vs. "Mykhacode" per the previously-analyzed installer's own signed metadata). That underlying product remains unresolved (see `project_t2auth_bastion_advinstaller_ambiguous.md`) — its ANY.RUN run in the earlier session ended mid-install before the actual application executed.
- Recommended follow-up: if further samples referencing productId `XPFFGCPBQ8TDT4` or the "T2Auth Bastion"/"Yanasofts"/"Mykhacode" identities surface, prioritize completing a full install-to-execution dynamic run of the actual downloaded package (not just this badge stub) to resolve the open question from the prior analysis.
- The publisher-name mismatch (Store listing "Yanasofts" vs. binary metadata "Mykhacode") is itself a minor red flag worth surfacing to whoever owns Microsoft Store listing integrity, independent of this file's own benign nature.
- KesaKode online/offline: no matches — expected, as KesaKode's function-matching requires native (x86/x64/ARM) code and this is pure .NET IL.
